## 🎯 نطاق البلاغات

### ✅ ضمن النطاق

- تجاوز المصادقة (bcrypt، المصادقة الثنائية)
- ثغرات CSRF رغم وجود الحمايات المطبَّقة
- إمكانية إعادة بناء سر شامير دون العدد المطلوب من الأجزاء
- كشف بيانات من المجلد `/private/`
- تنزيل ملفات حساسة (مثل قاعدة بيانات كلمات المرور) مع تجاوز تسجيل الدخول، مثلًا عبر رابط مباشر
- التعرّض لهجمات القوة الغاشمة رغم تحديد المعدل (rate limiting)
- XSS، حقن SQL *(رغم أن النظام لا يستخدم SQL)*

### ❌ خارج النطاق

- الهجمات التي تتطلب وصولًا فعليًا إلى الخادم
- هجمات الهندسة الاجتماعية ضد حاملي بطاقات Secret Key
- مشكلات إعداد خادم الويب من جانب المستخدم
- التقارير المُنشَأة تلقائيًا بواسطة أدوات الفحص دون إثبات مفهوم

## 🛡️ أفضل الممارسات عند النشر

> [!WARNING]
> Secret Key هو نظام **مُستضاف ذاتيًا (self-hosted)** — يعتمد أمان تثبيتك إلى حد كبير على إعدادات خادمك الخاص.

| | الممارسة |
|---|---|
| 📁 | احتفظ بمجلد `/private/` **خارج** `public_html` |
| 🔒 | استخدم HTTPS (SSL/TLS) على الخادم |
| 🔄 | حدِّث PHP بانتظام إلى أحدث إصدار من السلسلة 8.x |
| 🚫 | لا تكشف ملف `secret-key.php` علنًا أبدًا |
| 📥 | لا تربط مباشرة بملفات حساسة في المجلد العام — قدّمها عبر `download.php` (يتطلب جلسة، ويسجّل عمليات التنزيل) |
| 🔑 | استخدم كلمات مرور قوية وفريدة لكل حساب |
