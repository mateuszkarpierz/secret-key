通常のバグ、ドキュメントの誤字、改善提案は、通常どおり [GitHub の Issue](https://github.com/mateuszkarpierz/secret-key/issues) として報告してください — これが標準的な方法であり、何ら秘密にすべきことではありません。このページは**セキュリティ脆弱性のみ**を扱います（下記の[報告の範囲](#-報告の範囲)を参照）— これらについては公開の場で報告し**ない**でください。

## 📬 セキュリティ脆弱性の報告

> [!CAUTION]
> セキュリティ脆弱性は必ず非公開で、**dev@secretkey.website** にのみ報告してください — GitHubの公開Issueとして報告することは絶対にしないでください。パッチが公開される前にエクスプロイトを公に開示することは、システムを運用しているすべての人を危険にさらします。

### 報告方法

詳細な説明を次のアドレスに送ってください：**dev@secretkey.website**

### 報告に含めるべき内容

| | 項目 |
|---|---|
| 📝 | 脆弱性の説明と潜在的な影響 |
| 🔁 | 再現手順（概念実証） |
| 🏷️ | 影響を受けるシステムのバージョン |
| 💡 | 修正案*（任意）* |

### 期待できること

| 時間 | 対応 |
|---|---|
| **48時間** | 報告受領の確認 |
| **7日** | 進捗の報告 |
| 修正後 | 公開での謝辞*（ご希望の場合）* |

## 🏷️ サポート対象バージョン

常に**最新のリリースバージョン**がサポート対象です。旧バージョンに関する報告も受け付けますが、まずは最新のリリースへの更新をお願いしています — 一部の脆弱性はすでに修正されている可能性があります。

現在のバージョンは [Releases ページ](https://github.com/mateuszkarpierz/secret-key/releases)で確認できます。

## 🎯 報告の範囲

### ✅ 範囲内

- 認証のバイパス（bcrypt、2FA）
- 既存の保護策があるにもかかわらず存在するCSRF脆弱性
- 必要な数の断片なしにShamirの秘密を再構築できる可能性
- `/private/` ディレクトリからのデータ漏洩
- ログインをバイパスして機密ファイル（例：パスワードデータベース）をダウンロードできる問題（例：直接URL経由）
- レート制限があるにもかかわらずブルートフォース攻撃に対して脆弱であること
- XSS、SQLインジェクション*（このシステムはSQLを使用していませんが）*

### ❌ 範囲外

- サーバーへの物理的なアクセスを必要とする攻撃
- Secret Keyカード所持者に対するソーシャルエンジニアリング攻撃
- ユーザー側のWebサーバー設定の問題
- PoCのないスキャナーによる自動生成レポート

## 🛡️ デプロイのベストプラクティス

> [!WARNING]
> Secret Keyは**セルフホスト**型のシステムです — インストールのセキュリティは、大部分があなた自身のサーバーの設定に依存します。

| | プラクティス |
|---|---|
| 📁 | `/private/` ディレクトリを `public_html` の**外側**に保つ |
| 🔒 | サーバーでHTTPS（SSL/TLS）を使用する |
| 🔄 | PHPを定期的に最新の8.xバージョンに更新する |
| 🚫 | `secret-key.php` ファイルを絶対に公開しない |
| 📥 | 公開ディレクトリ内の機密ファイルに直接リンクしない — `download.php` を通して提供する（セッションが必要、ダウンロードをログに記録） |
| 🔑 | すべてのアカウントに強力で一意なパスワードを使用する |
