## Идея

Каждый из нас хранит десятки паролей — от банков, почты, социальных сетей, подписок. **Что с ними происходит после нашей смерти?** Семья теряет доступ к аккаунтам, не может отменить подписки, закрыть счета, вернуть деньги.

Secret Key решает эту проблему, создавая безопасный аварийный план с двумя гарантиями:

| &nbsp; | Проблема | Решение |
|---|---|---|
| 🔐 | Несанкционированный доступ **при жизни** владельца | Каждая попытка доступа требует пароль + SMS-код |
| 💀 | Потеря доступа к аккаунтам **после смерти** | Назначенные люди восстанавливают пароль с помощью алгоритма Шамира |

Система **полностью самостоятельно размещается (self-hosted)** — данные никогда не покидают ваш сервер. Никакой центральной базы данных, никакого облака, никаких внешних зависимостей, кроме отправки SMS.

<a name="stack"></a>

```
Backend         PHP 8+, файлы без БД (JSON + PHP-конфиг), никакого SQL
Авторизация     bcrypt cost=10, 2FA по SMS через API SMSPlanet
Криптография    Shamir Secret Sharing (secrets.js)
Frontend        Чистый HTML + JS, никаких внешних зависимостей (офлайн)
```

## Как это работает

В критической ситуации назначенные люди выполняют четыре шага:

```
┌──────────────────────────────────────────────────────────────────────┐
│                                                                      │
│  01  СБОР            Минимум 3 из 5 назначенных людей                │
│      ─────────       У каждого карта с фрагментом ключа              │
│                                                                      │
│  02  ВХОД             Учётные данные с карты Secret Key              │
│      ──────────      + SMS-код на привязанный номер телефона         │
│                                                                      │
│  03  ФРАГМЕНТЫ        Каждый вводит свой фрагмент или                 │
│      ─────────       сканирует QR-код с карты                        │
│                                                                      │
│  04  ДОСТУП           Пароль восстанавливается локально в браузере —  │
│      ────────        и никогда не попадает на сервер                  │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

**Без телефона, привязанного к аккаунту, войти невозможно** — даже зная данные с карты.  
**Без необходимого количества фрагментов восстановить пароль математически невозможно** — даже имея доступ к серверу.

## Карта Secret Key

Каждый назначенный человек получает персонализированный носитель с четырьмя элементами:

| Элемент | Описание |
|---|---|
| 🔑 **Логин и пароль** | Уникальные учётные данные — у каждого своя учётная запись с привязанным номером телефона |
| 🔢 **Фрагмент Шамира** | Фрагмент ключа в hex-формате — один из пяти, бесполезен без остальных |
| ⊞ **QR-код** | Тот же фрагмент, закодированный в QR — сканирование исключает ошибки ручного переписывания |
| 🌐 **Адрес системы** | URL вашего собственного экземпляра Secret Key — ведёт прямо на панель входа |

**Формат носителя может быть любым** — распечатанный лист, PDF, пластиковая карта. Важно, чтобы он содержал перечисленные выше четыре элемента.

## Алгоритм Шамира

Secret Key использует библиотеку [`secrets.js`](https://github.com/grempe/secrets.js) (форк [amper5and/secrets.js](https://github.com/amper5and/secrets.js), встроенный через [iancoleman.io/shamir](https://iancoleman.io/shamir/)) для разделения и восстановления секрета.

> [!NOTE]
> Используемая библиотека **идентична той, что используется на [iancoleman.io/shamir](https://iancoleman.io/shamir/)** — формат фрагментов полностью совместим, что позволяет независимую проверку вне системы.

### Разделение и восстановление секрета

```
Мастер-пароль: "MyKeePassPassword2024!"
         │
         ▼  Разделение на 5 фрагментов (порог: 3)
         │
    ┌────┴──────────────────────────────────┐
    │                                       │
    │  S1: 801a3f9c2e4b7d1...  →  Человек A │  Каждый фрагмент
    │  S2: 802c8f1a5e9b3d7...  →  Человек B │  бесполезен без
    │  S3: 803e2a7f4c1b9d5...  →  Человек C │  необходимого
    │  S4: 804b6d3e8f2a1c9...  →  Человек D │  количества
    │  S5: 805d9f7b2e4c3a1...  →  Человек E │  остальных
    │                                       │
    └────┬──────────────────────────────────┘
         │
         ▼  Восстановление — достаточно любых 3 из 5
         │
    S1 + S2 + S3  →  "MyKeePassPassword2024!"  ✓
    S2 + S4 + S5  →  "MyKeePassPassword2024!"  ✓
    S1            →  никакой информации о секрете  ✗
```

### Криптографические свойства

Секрет кодируется как свободный член многочлена над полем GF(2⁸). Каждый фрагмент — это точка на этом многочлене; зная необходимое количество точек, его можно однозначно восстановить с помощью интерполяции Лагранжа:

```
f(x) = a₀ + a₁x + a₂x² + ... + aₖ₋₁xᵏ⁻¹  (mod p)
```

> [!IMPORTANT]
> Обладание **меньшим, чем требуется,** количеством фрагментов не даёт **никакой** информации о секрете (information-theoretic security). Дополнительный паддинг в 1024 бита предотвращает атаки на маленькие секреты.

### Параметры реализации

| Параметр | Значение |
|---|---|
| Библиотека | secrets.js (форк grempe, через iancoleman.io/shamir) |
| Формат фрагмента | `8` + 2-hex x-координата + данные |
| minPad | 1024 бита |
| Кодировка | UTF-8 (str2hex) |
| Восстановление | JavaScript на стороне браузера — пароль никогда не попадает на сервер |

### Выбор параметров разделения

| Всего фрагментов | Необходимый минимум | Сценарий |
|---|---|---|
| 3 | 2 | Небольшая семья |
| 5 | 3 | Стандарт *(рекомендуется)* |
| 7 | 4 | Большая семья / компания |

## Архитектура системы

Пользователь последовательно проходит несколько уровней проверки, прежде чем получить доступ к защищённым ресурсам:

```
Пользователь →  вводит логин + пароль
                         │
Система PHP  →  проверяет пароль (bcrypt), проверяет rate limiting и CSRF
                         │
SMS / 2FA    →  отправляет одноразовый код на привязанный номер
                         │
Пользователь →  вводит SMS-код
                         │
Система PHP  →  проверяет код, создаёт сессию, опционально запоминает устройство
                         │
Браузер      →  принимает фрагменты Шамира, восстанавливает секрет локально на JS
```

### Уровни системы

**Уровень авторизации** (`/app/`)
- `login.php` — форма входа
- `auth.php` — логика сессии, bcrypt, 2FA, защита от брутфорса, CSRF, а также вспомогательные функции `t()` (тексты интерфейса), `md_lite()` (упрощённый markdown), `empty_state_box()`
- `verify.php` — проверка SMS-кода
- `resend.php` — повторная отправка SMS
- `logout.php` — выход из системы

**Уровень доступа** (`/decrypt/`)
- `index.php` — панель расшифровки с восстановлением по Шамиру на JS
- `download.php` — контролируемая выдача файлов (требует сессию, белый список, построенный из конфигурации, логирование на стороне сервера)
- `log.php` — логирование событий
- `devtools-log.php` — логирование попыток открытия DevTools (с ограничением частоты по IP)

**Уровень данных** (`/private/` — за пределами `public_html`)
- `secret-key.php` — единый файл конфигурации: люди (`$people`), файлы для скачивания (`$downloads`), инструкция (`$instructions`), email-уведомление (`$email_notify`), домен для SMS
- `lang.php` — тексты интерфейса (только один язык, без переключателя — см. [Установка](#установка))
- `rate-limit.php` — постоянное ограничение частоты (счётчики независимы от сессии)
- `rate_limits.json` — счётчики попыток входа по IP/аккаунту *(создаётся автоматически)*
- `trusted_devices.json` — токены доверенных устройств *(создаётся автоматически)*
- `secret-key.log` — журналы событий
- `moja-baza-hasel.kdbx` *(и другие файлы для скачивания)* — отдаются только через `download.php`, никогда напрямую через HTTP

> [!WARNING]
> Все чувствительные конфигурационные файлы хранятся **за пределами публичной директории** сервера — неправильная настройка веб-сервера не создаёт риска их раскрытия.

## Безопасность

Система объединяет **восемь независимых уровней защиты** — компрометация одного из них не даёт доступа к системе.

| Уровень | Механизм | Подробности |
|---|---|---|
| 🔒 **Пароли** | bcrypt | cost=10, формат `$2y$`, проверка, устойчивая к атакам по времени |
| 🛡️ **CSRF** | Токен из 64 hex-символов | Генерируется криптографически, проверяется на каждой конечной точке, изменяющей состояние (вход, проверка 2FA, повторная отправка SMS, выход из системы, журнал событий) |
| 🚫 **Брутфорс** | Rate limiting | 3 попытки/IP + 3 попытки/аккаунт за 15 минут; 3 неверных SMS-кода/час. Постоянные счётчики на стороне сервера (файл, независимый от сессии/куки клиента) |
| 📱 **2FA по SMS** | 6-значный код | Генерируется криптографически, действует 10 минут, задержка 60 секунд между отправками |
| 💻 **Доверенные устройства** | SHA-256, HttpOnly | Secure + SameSite=Strict, файл за пределами `public_html`, TTL 7 дней |
| ⏱️ **Сессия** | Автовыход | Cookie сессии с явными флагами HttpOnly + Secure + SameSite=Strict; тайм-аут 30 минут, регенерация ID сессии после каждой проверки |
| 🖥️ **Защита интерфейса** | Обнаружение DevTools | Обнаруживает инструменты разработчика, физически удаляет DOM, логирует инцидент с IP, REF# и длительностью |
| 📥 **Контролируемые загрузки** | `download.php` + белый список | Файлы для скачивания находятся за пределами `public_html`; требуется активная сессия, никакого прямого URL, всегда логируется на стороне сервера |

## Установка

### Требования

- PHP 8.0+
- Веб-сервер (Apache / Nginx)
- Аккаунт в [SMSPlanet](https://smsplanet.pl) (для отправки кодов 2FA)
- Доступ к директории за пределами `public_html`

---

### Шаг 1 — Конфигурация (офлайн)

Откройте `dashboard.html` локально в браузере. Он содержит две вкладки:

**Конфигурация** — генерирует файл `secret-key.php`:
1. Токен API SMSPlanet, имя отправителя SMS и домен для автозаполнения кода (Android/iOS) — только домен, без `@` и без `https://`
2. Для каждого назначенного человека: логин, пароль, имя, фамилия, номер телефона и должен ли он быть виден в списке держателей на панели
3. Файлы для скачивания (база паролей, база 2FA, установщик программы) — ключ, подпись кнопки, имя файла
4. Шаги инструкции для панели (форматирование: `**жирный**` / `*курсив*`)
5. Опционально: email-уведомление при каждом входе (адрес получателя, отправитель, ссылка на панель)
6. Нажмите «Сгенерировать конфигурацию» и скачайте полученный файл `secret-key.php`

**Шифрование** — разделяет мастер-пароль на фрагменты Шамира:
1. Введите мастер-пароль базы паролей
2. Задайте общее количество фрагментов и необходимый минимум
3. Нажмите «Сгенерировать фрагменты»
4. Скачайте файл `secret-key-shares.txt`

> [!TIP]
> Оба инструмента работают **полностью офлайн** — никакие данные не покидают браузер. Форма генерирует `secret-key.php` с нуля при каждом запуске — она не загружает и не редактирует существующий файл.

---

### Шаг 2 — Загрузка на сервер

```bash
/home/user/
├── public_html/
│   ├── app/           ← содержимое папки /app/
│   └── decrypt/       ← содержимое папки /decrypt/
└── private/           ← ЗА ПРЕДЕЛАМИ public_html
    ├── secret-key.php  ← сгенерированный файл конфигурации
    ├── lang.php        ← тексты интерфейса (один язык, см. шаг 1)
    ├── rate-limit.php  ← системный файл из репозитория (rate limiting)
    └── moja-baza-hasel.kdbx  ← ваши файлы (выдаются через download.php)
```

> [!WARNING]
> `lang.php` должен быть загружен на сервер **вместе с** `secret-key.php`. `auth.php` загружает его через `require_once` — отсутствие файла обрушивает всю систему (фатальная ошибка на каждой странице), а не только переводы.

---

### Шаг 3 — Путь к конфигурации

В файле `auth.php` обновите путь к файлу конфигурации:

```php
require_once '/home/user/private/secret-key.php';
```

---

### Шаг 4 — Домен в содержимом SMS (WebOTP)

Содержимое отправляемого SMS-кода заканчивается строкой `@домен #код` — это формат, требуемый [WebOTP API](https://developer.mozilla.org/en-US/docs/Web/API/WebOTP_API), благодаря которому браузер телефона сам заполняет поле кода, без ручного переписывания из SMS.

Домен задаётся на **шаге 1**, в форме дашборда (поле «Домен для автозаполнения SMS») — вводите только сам домен, без `@` и без `https://` (дашборд добавляет `@` автоматически). В конфигурации он выглядит так:

```php
define('SMS_AUTOFILL_DOMAIN', '@ваш-домен.ru');
```

> [!WARNING]
> Домен должен **точно** совпадать с тем, под которым вы размещаете систему — иначе WebOTP проигнорирует SMS и автозаполнение не сработает. Код всё равно придёт и сработает при ручном вводе, просто без этого удобства.

---

### Шаг 5 — Распространение карт

Для каждого назначенного человека подготовьте носитель с:
- логином и паролем (из вкладки «Конфигурация»)
- фрагментом Шамира (из файла `secret-key-shares.txt`)
- опционально: QR-кодом с тем же фрагментом
- адресом вашего экземпляра системы

## Часто задаваемые вопросы

<details>
<summary><strong>Что будет, если я потеряю карту Secret Key?</strong></summary>

Сама карта бесполезна без доступа к телефону, привязанному к этому аккаунту — вход требует SMS-подтверждения. Риск ограничен, но владелец должен быть уведомлён и рассмотреть возможность генерации новой конфигурации с новым набором фрагментов.

</details>

<details>
<summary><strong>Могу ли я самостоятельно прочитать пароль, имея только одну карту?</strong></summary>

Нет. Это математически невозможно. Один фрагмент не раскрывает никакой информации о секрете — это свойство алгоритма, называемое information-theoretic security. Восстановить мастер-пароль позволяет только сбор необходимого количества фрагментов.

</details>

<details>
<summary><strong>Что если один из назначенных людей умрёт или станет недоступен?</strong></summary>

Система спроектирована с избыточностью — достаточно собрать минимально необходимое количество фрагментов (например, 3 из 5). Недоступность одного-двух человек не блокирует аварийную процедуру, если остальные могут собраться.

</details>

<details>
<summary><strong>Попадает ли пароль на сервер во время расшифровки?</strong></summary>

Нет. Восстановление пароля из фрагментов Шамира происходит **полностью на стороне браузера** (JavaScript). Сервер используется только для аутентификации пользователя — сам секрет никогда его не покидает.

</details>

<details>
<summary><strong>Могу ли я использовать систему с другим менеджером паролей, не KeePassXC?</strong></summary>

Да. Secret Key хранит и восстанавливает **любой мастер-пароль** — независимо от используемого менеджера. Совместим с любой программой, поддерживающей мастер-пароль: KeePassXC, Bitwarden, 1Password и другими.

</details>

<details>
<summary><strong>Как выбрать порог — сколько фрагментов требуется?</strong></summary>

Чем выше порог, тем выше безопасность — но и тем труднее собрать всех в критической ситуации. Рекомендуемый компромисс для стандартного использования — **3 из 5**: допускает недоступность двух человек при сохранении хорошего уровня защиты.

</details>

<details>
<summary><strong>Как долго действительны учётные данные с карты?</strong></summary>

Бессрочно — до тех пор, пока владелец не сгенерирует новую конфигурацию и не заменит файл `secret-key.php` на сервере. После этой операции старые карты перестают работать, и нужно распространить новые среди всех назначенных людей.

</details>
