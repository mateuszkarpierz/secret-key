## الفكرة

كل واحد منا يخزّن عشرات كلمات المرور — للبنوك، والبريد الإلكتروني، ووسائل التواصل الاجتماعي، والاشتراكات. **ماذا يحدث لها بعد وفاتنا؟** تُقطَع العائلة عن الحسابات، ولا تستطيع إلغاء الاشتراكات، أو إغلاق الحسابات، أو استرجاع الأموال.

يحل Secret Key هذه المشكلة عن طريق إنشاء خطة طوارئ آمنة بضمانتين:

| &nbsp; | المشكلة | الحل |
|---|---|---|
| 🔐 | الوصول غير المُصرَّح به **أثناء حياة** المالك | كل محاولة وصول تتطلب كلمة مرور + رمز SMS |
| 💀 | فقدان الوصول إلى الحسابات **بعد الوفاة** | يقوم الأشخاص المحدَّدون بإعادة بناء كلمة المرور باستخدام خوارزمية شامير |

النظام **مُستضاف ذاتيًا بالكامل** — لا تغادر البيانات خادمك مطلقًا. لا قاعدة بيانات مركزية، ولا سحابة، ولا اعتماديات خارجية بخلاف إرسال الرسائل النصية.

<a name="stack"></a>

```
الخلفية (Backend)      PHP 8+، ملفات مسطحة (JSON + إعدادات PHP)، بدون SQL
التفويض                bcrypt cost=10، مصادقة ثنائية عبر SMS باستخدام واجهة SMSPlanet
التشفير                Shamir Secret Sharing (secrets.js)
الواجهة (Frontend)     HTML + JS خالص، بدون اعتماديات خارجية (يعمل دون اتصال)
```

```
┌──────────────────────────────────────────────────────────────────────┐

│                                                                      │
│  02  تسجيل الدخول     بيانات تسجيل الدخول من بطاقة Secret Key        │
│      ──────────      + رمز SMS يُرسَل إلى رقم الهاتف المخصَّص         │
│                                                                      │
│  03  الأجزاء           يُدخل كل شخص جزءه أو                          │
│      ─────────       يمسح رمز QR الموجود على البطاقة                 │
│                                                                      │
│  04  الوصول            تُعاد بناء كلمة المرور محليًا في المتصفح —      │
```

**بدون الهاتف المخصَّص للحساب، يصبح تسجيل الدخول مستحيلًا** — حتى مع معرفة بيانات البطاقة.  
**بدون العدد المطلوب من الأجزاء، تصبح إعادة بناء كلمة المرور مستحيلة رياضيًا** — حتى مع الوصول إلى الخادم.

## بطاقة Secret Key

يحصل كل شخص محدَّد على وسيلة مخصَّصة تحتوي على أربعة عناصر:

| العنصر | الوصف |
|---|---|
| 🔑 **اسم المستخدم وكلمة المرور** | بيانات وصول فريدة — لكل شخص حسابه الخاص المرتبط برقم هاتف مخصَّص |
| 🔢 **جزء شامير** | جزء من المفتاح بصيغة سداسية عشرية — واحد من خمسة، لا فائدة منه بدون البقية |
| ⊞ **رمز QR** | نفس الجزء مُرمَّز كرمز QR — المسح يزيل أخطاء النسخ اليدوي |
| 🌐 **عنوان النظام** | عنوان URL لنسخة Secret Key الخاصة بك — يقود مباشرة إلى لوحة تسجيل الدخول |

**صيغة الوسيلة حرة** — ورقة مطبوعة، ملف PDF، بطاقة بلاستيكية. المهم أن تحتوي على العناصر الأربعة المذكورة أعلاه.

## خوارزمية شامير

يستخدم Secret Key مكتبة [`secrets.js`](https://github.com/amper5and/secrets.js) لتقسيم السر وإعادة بنائه.

> [!NOTE]
> المكتبة المستخدَمة **مطابقة** لتلك المستخدَمة في [iancoleman.io/shamir](https://iancoleman.io/shamir/) — صيغة الأجزاء متوافقة تمامًا، مما يسمح بالتحقق المستقل خارج النظام.

### تقسيم السر وإعادة بنائه

```
كلمة المرور الرئيسية: "MyKeePassPassword2024!"
         │
         ▼  التقسيم إلى 5 أجزاء (الحد الأدنى: 3)
         │
    ┌────┴──────────────────────────────────┐
    │                                       │
    │  S1: 801a3f9c2e4b7d1...  →  الشخص A   │  كل جزء
    │  S2: 802c8f1a5e9b3d7...  →  الشخص B   │  لا فائدة منه
    │  S3: 803e2a7f4c1b9d5...  →  الشخص C   │  بدون العدد
    │  S4: 804b6d3e8f2a1c9...  →  الشخص D   │  المطلوب من
    │  S5: 805d9f7b2e4c3a1...  →  الشخص E   │  البقية
    │                                       │
    └────┬──────────────────────────────────┘
         │
         ▼  إعادة البناء — يكفي 3 من أصل 5 أيًّا كانت
         │
    S1 + S2 + S3  →  "MyKeePassPassword2024!"  ✓
    S2 + S4 + S5  →  "MyKeePassPassword2024!"  ✓
    S1            →  لا توجد أي معلومة عن السر  ✗
```

### الخصائص التشفيرية

يُرمَّز السر كحدٍّ ثابت لكثيرة حدود على الحقل GF(2⁸). كل جزء هو نقطة على تلك كثيرة الحدود — ومع معرفة العدد المطلوب من النقاط، يمكن إعادة بنائه بشكل فريد عبر استيفاء لاغرانج:

```
f(x) = a₀ + a₁x + a₂x² + ... + aₖ₋₁xᵏ⁻¹  (mod p)
```

> [!IMPORTANT]
> امتلاك عدد **أقل من المطلوب** من الأجزاء لا يوفّر **أي** معلومة عن السر (information-theoretic security). الحشو الإضافي بـ 1024 بت يمنع الهجمات على الأسرار الصغيرة.

### معطيات التنفيذ

| المعطى | القيمة |
|---|---|
| المكتبة | secrets.js (amper5and) — متوافقة مع iancoleman.io |
| صيغة الجزء | `8` + إحداثي x من رقمين سداسيَّين + البيانات |
| minPad | 1024 بت |
| الترميز | UTF-8 (str2hex) |
| إعادة البناء | JavaScript من جانب المتصفح — كلمة المرور لا تصل إلى الخادم أبدًا |

### اختيار معطيات التقسيم

| إجمالي الأجزاء | الحد الأدنى المطلوب | السيناريو |
|---|---|---|
| 3 | 2 | عائلة صغيرة |
| 5 | 3 | قياسي *(مُوصى به)* |
| 7 | 4 | عائلة كبيرة / شركة |

## بنية النظام

يمر المستخدم بعدة مستويات تحقق متتالية قبل الحصول على الوصول إلى الموارد المحمية:

```
المستخدم       →  يُدخل اسم المستخدم + كلمة المرور
                         │
نظام PHP        →  يتحقق من كلمة المرور (bcrypt)، ويفحص تحديد المعدل وCSRF
                         │
SMS / 2FA       →  يُرسل رمزًا لمرة واحدة إلى الرقم المخصَّص
                         │
المستخدم       →  يُدخل رمز SMS
                         │
نظام PHP        →  يتحقق من الرمز، ينشئ جلسة، ويتذكّر الجهاز اختياريًا
                         │
المتصفح         →  يستقبل أجزاء شامير، ويعيد بناء السر محليًا بلغة JS
```

### مستويات النظام

**مستوى التفويض** (`/app/`)
- `login.php` — نموذج تسجيل الدخول
- `auth.php` — منطق الجلسة، bcrypt، المصادقة الثنائية، الحماية من الهجمات العنيفة، CSRF، بالإضافة إلى الدوال المساعدة `t()` (نصوص الواجهة)، `md_lite()` (ماركداون مبسّط)، `empty_state_box()`
- `verify.php` — التحقق من رمز SMS
- `resend.php` — إعادة إرسال SMS
- `logout.php` — تسجيل الخروج

**مستوى الوصول** (`/decrypt/`)
- `index.php` — لوحة فك التشفير مع إعادة بناء شامير بلغة JS
- `download.php` — تنزيلات ملفات مُراقَبة (تتطلب جلسة، قائمة سماح مبنية من الإعدادات، تسجيل من جانب الخادم)
- `log.php` — تسجيل الأحداث
- `devtools-log.php` — تسجيل محاولات فحص أدوات المطوّرين (مع تحديد معدل حسب IP)

**مستوى البيانات** (`/private/` — خارج `public_html`)
- `secret-key.php` — ملف إعدادات واحد: الأشخاص (`$people`)، الملفات القابلة للتنزيل (`$downloads`)، التعليمات (`$instructions`)، إشعار البريد الإلكتروني (`$email_notify`)، نطاق SMS
- `lang.php` — نصوص الواجهة (لغة واحدة فقط، بلا مبدّل — انظر [التثبيت](#التثبيت))
- `rate-limit.php` — تحديد معدل دائم (عدّادات مستقلة عن الجلسة)
- `rate_limits.json` — عدّادات محاولات تسجيل الدخول حسب IP/الحساب *(يُنشَأ تلقائيًا)*
- `trusted_devices.json` — رموز الأجهزة الموثوقة *(يُنشَأ تلقائيًا)*
- `secret-key.log` — سجلات الأحداث
- `moja-baza-hasel.kdbx` *(وملفات أخرى قابلة للتنزيل)* — تُقدَّم فقط عبر `download.php`، أبدًا مباشرة عبر HTTP

> [!WARNING]
> جميع ملفات الإعدادات الحساسة مخزَّنة **خارج المجلد العام** للخادم — الإعداد الخاطئ لخادم الويب لا يشكّل خطر كشفها.

## الأمان

يجمع النظام بين **ثماني مستويات حماية مستقلة** — اختراق واحدة منها لا يمنح الوصول إلى النظام.

| المستوى | الآلية | التفاصيل |
|---|---|---|
| 🔒 **كلمات المرور** | bcrypt | cost=10، صيغة `$2y$`، تحقق مقاوم لهجمات التوقيت |
| 🛡️ **CSRF** | رمز من 64 خانة سداسية عشرية | يُنشَأ تشفيريًا، يُتحقَّق منه في كل نقطة نهاية تغيّر الحالة (تسجيل الدخول، التحقق الثنائي، إعادة إرسال SMS، سجل الأحداث) |
| 🚫 **الهجمات العنيفة** | تحديد المعدل | 3 محاولات لكل IP + 3 محاولات لكل حساب في نافذة 15 دقيقة؛ 3 رموز SMS خاطئة في الساعة. عدّادات دائمة من جانب الخادم (ملف، مستقل عن جلسة/كوكيز العميل) |
| 📱 **المصادقة الثنائية عبر SMS** | رمز من 6 أرقام | يُنشَأ تشفيريًا، صالح لمدة 10 دقائق، فترة انتظار 60 ثانية بين عمليات الإرسال |
| 💻 **الأجهزة الموثوقة** | SHA-256، HttpOnly | Secure + SameSite=Strict، ملف خارج `public_html`، مدة صلاحية 7 أيام |
| ⏱️ **الجلسة** | تسجيل خروج تلقائي | كوكي جلسة بعلامات صريحة HttpOnly + Secure + SameSite=Strict؛ مهلة 30 دقيقة، إعادة إنشاء معرّف الجلسة بعد كل تحقق |
| 🖥️ **حماية الواجهة** | اكتشاف أدوات المطوّرين | يكتشف أدوات المطوّرين، ويحذف DOM فعليًا، ويسجّل الحادثة مع IP و REF# والمدة |
| 📥 **تنزيلات مُراقَبة** | `download.php` + قائمة سماح | الملفات القابلة للتنزيل موجودة خارج `public_html`؛ تتطلب جلسة نشطة، بلا رابط مباشر، وتُسجَّل دائمًا من جانب الخادم |

## التثبيت

### المتطلبات

- PHP 8.0+
- خادم ويب (Apache / Nginx)
- حساب في [SMSPlanet](https://smsplanet.pl) (لإرسال رموز المصادقة الثنائية)
- الوصول إلى مجلد خارج `public_html`

---

### الخطوة 1 — الإعداد (دون اتصال)

افتح `dashboard.html` محليًا في متصفحك. يحتوي على تبويبين:

**الإعداد** — يُنشئ ملف `secret-key.php`:
1. رمز واجهة SMSPlanet، اسم مُرسِل SMS، والنطاق الخاص بالتعبئة التلقائية للرمز (Android/iOS) — فقط النطاق، بدون `@` وبدون `https://`
2. لكل شخص محدَّد: اسم المستخدم، كلمة المرور، الاسم الأول، اسم العائلة، رقم الهاتف، وما إذا كان يجب أن يظهر في قائمة الحاملين في اللوحة
3. الملفات القابلة للتنزيل (قاعدة بيانات كلمات المرور، قاعدة بيانات المصادقة الثنائية، مثبِّت البرنامج) — المفتاح، تسمية الزر، اسم الملف
4. خطوات التعليمات الخاصة باللوحة (التنسيق: `**عريض**` / `*مائل*`)
5. اختياري: إشعار بريد إلكتروني عند كل تسجيل دخول (عنوان المستلم، المُرسِل، رابط اللوحة)
6. اضغط على "إنشاء الإعدادات" وقم بتنزيل ملف `secret-key.php` الناتج

**التشفير** — يقسّم كلمة المرور الرئيسية إلى أجزاء شامير:
1. أدخل كلمة المرور الرئيسية لقاعدة بيانات كلمات المرور
2. حدّد العدد الإجمالي للأجزاء والحد الأدنى المطلوب
3. اضغط على "إنشاء الأجزاء"
4. قم بتنزيل ملف `secret-key-shares.txt`

> [!TIP]
> تعمل كلتا الأداتين **دون اتصال بالإنترنت تمامًا** — لا تغادر أي بيانات المتصفح. ينشئ النموذج ملف `secret-key.php` من الصفر في كل مرة يُشغَّل فيها — لا يُحمِّل أو يُحرِّر ملفًا موجودًا.

---

### الخطوة 2 — الرفع إلى الخادم

```bash
/home/user/
├── public_html/
│   ├── app/           ← محتوى مجلد /app/
│   └── decrypt/       ← محتوى مجلد /decrypt/
└── private/           ← خارج public_html
    ├── secret-key.php  ← ملف الإعدادات المُنشَأ
    ├── lang.php        ← نصوص الواجهة (لغة واحدة، انظر الخطوة 1)
    ├── rate-limit.php  ← ملف نظام من المستودع (تحديد المعدل)
    └── moja-baza-hasel.kdbx  ← ملفاتك (تُقدَّم عبر download.php)
```

> [!WARNING]
> يجب رفع `lang.php` إلى الخادم **مع** `secret-key.php`. يُحمِّله `auth.php` عبر `require_once` — غياب الملف يُعطِّل النظام بأكمله (خطأ فادح في كل صفحة)، لا الترجمات فقط.

---

### الخطوة 3 — مسار الإعدادات

في ملف `auth.php`، حدّث المسار إلى ملف الإعدادات:

```php

```

### الخطوة 4 — النطاق في محتوى SMS (WebOTP)

ينتهي محتوى رمز SMS المُرسَل بسطر `@النطاق #الرمز` — هذه هي الصيغة التي تتطلبها [واجهة WebOTP](https://developer.mozilla.org/en-US/docs/Web/API/WebOTP_API)، وبفضلها يعبّئ متصفح الهاتف حقل الرمز تلقائيًا، دون الحاجة لنسخه يدويًا من الرسالة.

تُحدِّد النطاق في **الخطوة 1**، في نموذج لوحة التحكم (حقل "نطاق التعبئة التلقائية لـ SMS") — تُدخل فقط النطاق، بدون `@` وبدون `https://` (تضيف لوحة التحكم `@` تلقائيًا). يدخل الإعدادات على هذا الشكل:

```php
define('SMS_AUTOFILL_DOMAIN', '@your-domain.com');
```

> [!WARNING]
> يجب أن يتطابق النطاق **تمامًا** مع النطاق الذي تستضيف عليه النظام فعليًا — وإلا فسيتجاهل WebOTP رسالة SMS ولن تعمل التعبئة التلقائية. سيصل الرمز ويعمل عند إدخاله يدويًا، لكن دون هذه الميزة.

---

### الخطوة 5 — توزيع البطاقات

لكل شخص محدَّد، جهّز وسيلة تحتوي على:
- اسم مستخدم وكلمة مرور (من تبويب الإعداد)
- جزء شامير (من ملف `secret-key-shares.txt`)
- اختياريًا: رمز QR يحمل نفس الجزء
- عنوان نسخة نظامك

## الأسئلة الشائعة

<details>
<summary><strong>ماذا يحدث إذا فقدت بطاقة Secret Key الخاصة بي؟</strong></summary>

البطاقة بمفردها لا فائدة منها بدون الوصول إلى الهاتف المخصَّص لذلك الحساب — يتطلب تسجيل الدخول تحقّقًا عبر SMS. الخطر محدود، لكن ينبغي إخبار المالك والنظر في إنشاء إعدادات جديدة بمجموعة جديدة من الأجزاء.

</details>

<details>
<summary><strong>هل يمكنني قراءة كلمة المرور بمفردي ببطاقة واحدة فقط؟</strong></summary>

لا. هذا مستحيل رياضيًا. جزء واحد لا يكشف أي معلومة عن السر — هذه خاصية للخوارزمية تُسمّى information-theoretic security. فقط جمع العدد المطلوب من الأجزاء يسمح بإعادة بناء كلمة المرور الرئيسية.

</details>

<details>
<summary><strong>ماذا لو توفي أحد الأشخاص المحدَّدين أو أصبح غير متاح؟</strong></summary>

صُمِّم النظام بتكرار (redundancy) — يكفي جمع الحد الأدنى المطلوب من الأجزاء (مثلًا 3 من أصل 5). عدم توفر شخص أو شخصين لا يعطّل إجراء الطوارئ، ما دام بقية الأشخاص قادرين على التجمّع.

</details>

<details>
<summary><strong>هل تصل كلمة المرور إلى الخادم خلال عملية فك التشفير؟</strong></summary>

لا. تتم إعادة بناء كلمة المرور من أجزاء شامير **بالكامل من جانب المتصفح** (JavaScript). يُستخدَم الخادم فقط لمصادقة المستخدم — السر نفسه لا يغادره أبدًا.

</details>

<details>
<summary><strong>هل يمكنني استخدام النظام مع مدير كلمات مرور آخر غير KeePassXC؟</strong></summary>

نعم. يخزّن Secret Key ويعيد بناء **أي كلمة مرور رئيسية** — بغض النظر عن المدير المستخدَم. متوافق مع أي برنامج يدعم كلمة مرور رئيسية: KeePassXC، Bitwarden، 1Password وغيرها.

</details>

<details>
<summary><strong>كيف أختار الحد الأدنى — كم عدد الأجزاء المطلوبة؟</strong></summary>

كلما ارتفع الحد الأدنى، زاد الأمان — لكن أصبح جمع الجميع في حالة الطوارئ أكثر صعوبة. التوازن المُوصى به للاستخدام القياسي هو **3 من أصل 5** — يسمح بعدم توفر شخصين مع الحفاظ على مستوى حماية جيد.

</details>

<details>
<summary><strong>إلى متى تظل بيانات تسجيل الدخول من البطاقة صالحة؟</strong></summary>

إلى أجل غير محدَّد — طالما لم يُنشئ المالك إعدادات جديدة ويستبدل ملف `secret-key.php` على الخادم. بعد هذه العملية، تتوقف البطاقات القديمة عن العمل، ويجب توزيع بطاقات جديدة على جميع الأشخاص المحدَّدين.

</details>
