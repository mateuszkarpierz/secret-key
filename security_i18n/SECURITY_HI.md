## 🏷️ समर्थित संस्करण

हमेशा **नवीनतम जारी किया गया संस्करण** समर्थित होता है। पुराने संस्करणों से संबंधित रिपोर्ट स्वीकार की जाती हैं, लेकिन पहले नवीनतम रिलीज़ में अपडेट करने का अनुरोध किया जाता है — हो सकता है कुछ कमज़ोरियाँ पहले ही ठीक कर दी गई हों।

वर्तमान संस्करण आप [Releases पेज](https://github.com/mateuszkarpierz/secret-key/releases) पर पा सकते हैं।

## 🎯 रिपोर्टिंग का दायरा

### ✅ दायरे में शामिल

- प्रमाणीकरण को बायपास करना (bcrypt, 2FA)
- लागू सुरक्षा उपायों के बावजूद CSRF कमज़ोरियाँ
- आवश्यक संख्या में शेयरों के बिना शमीर के रहस्य को पुनर्निर्मित करने की संभावना
- `/private/` डायरेक्टरी से डेटा का उजागर होना
- लॉगिन को बायपास करके संवेदनशील फ़ाइलें (जैसे पासवर्ड डेटाबेस) डाउनलोड करना, जैसे किसी सीधे URL के ज़रिए
- रेट लिमिटिंग के बावजूद ब्रूट-फ़ोर्स हमलों की संवेदनशीलता
- XSS, SQL इंजेक्शन *(हालाँकि सिस्टम SQL का उपयोग नहीं करता)*

### ❌ दायरे से बाहर

- ऐसे हमले जिनके लिए सर्वर तक भौतिक एक्सेस आवश्यक हो
- Secret Key कार्ड धारकों के विरुद्ध सोशल इंजीनियरिंग हमले
- उपयोगकर्ता की ओर से वेब सर्वर कॉन्फ़िगरेशन की समस्याएँ
- बिना PoC के स्कैनर द्वारा स्वचालित रूप से जनरेट की गई रिपोर्ट

## 🛡️ डिप्लॉयमेंट की सर्वोत्तम प्रथाएँ

> [!WARNING]
> Secret Key एक **सेल्फ़-होस्टेड** सिस्टम है — आपके इंस्टॉलेशन की सुरक्षा काफ़ी हद तक आपके अपने सर्वर के कॉन्फ़िगरेशन पर निर्भर करती है।

| | प्रथा |
|---|---|
| 📁 | `/private/` डायरेक्टरी को `public_html` से **बाहर** रखें |
| 🔒 | सर्वर पर HTTPS (SSL/TLS) का उपयोग करें |
| 🔄 | PHP को नियमित रूप से नवीनतम 8.x संस्करण में अपडेट करें |
| 🚫 | `secret-key.php` फ़ाइल को कभी सार्वजनिक न करें |
| 📥 | पब्लिक डायरेक्टरी में संवेदनशील फ़ाइलों को सीधे लिंक न करें — उन्हें `download.php` के ज़रिए उपलब्ध कराएँ (सेशन आवश्यक, डाउनलोड लॉग होते हैं) |
| 🔑 | हर खाते के लिए मज़बूत, अनूठे पासवर्ड का उपयोग करें |
