## 📬 Как сообщить об уязвимости безопасности

> [!CAUTION]
> Сообщайте об уязвимостях безопасности только приватно, на **dev@secretkey.website** — никогда как публичный Issue на GitHub. Публичное раскрытие эксплойта до выпуска исправления подвергает риску всех, у кого развёрнута система.

### Как сообщить

Отправьте подробное описание на: **dev@secretkey.website**

### Что включить в отчёт

| | Элемент |
|---|---|
| 📝 | Описание уязвимости и её потенциального воздействия |
| 🔁 | Шаги для воспроизведения (proof of concept) |
| 🏷️ | Версия системы, которой это касается |
| 💡 | Предложение по исправлению *(необязательно)* |

### Чего ожидать

| Время | Ответ |
|---|---|
| **48 часов** | Подтверждение получения отчёта |
| **7 дней** | Информация о прогрессе |
| После исправления | Публичная благодарность *(если пожелаете)* |

## 🎯 Область отчётов

### ✅ В области действия

- Обход аутентификации (bcrypt, 2FA)
- Уязвимости CSRF несмотря на применённые меры защиты
- Возможность восстановить секрет Шамира без необходимого количества фрагментов
- Раскрытие данных из директории `/private/`
- Скачивание чувствительных файлов (например, базы паролей) в обход входа в систему, например через прямой URL
- Уязвимость к атакам методом перебора (brute-force) несмотря на rate limiting
- XSS, SQL Injection *(хотя система не использует SQL)*

### ❌ Вне области действия

- Атаки, требующие физического доступа к серверу
- Атаки социальной инженерии на держателей карт Secret Key
- Проблемы с конфигурацией веб-сервера на стороне пользователя
- Отчёты, автоматически сгенерированные сканерами без PoC

## 🛡️ Лучшие практики при развёртывании

> [!WARNING]
> Secret Key — это **самостоятельно размещаемая (self-hosted)** система — безопасность вашей установки в значительной степени зависит от конфигурации вашего собственного сервера.

| | Практика |
|---|---|
| 📁 | Держите директорию `/private/` **за пределами** `public_html` |
| 🔒 | Используйте HTTPS (SSL/TLS) на сервере |
| 🔄 | Регулярно обновляйте PHP до последней версии 8.x |
| 🚫 | Никогда не раскрывайте файл `secret-key.php` публично |
| 📥 | Не ссылайтесь напрямую на чувствительные файлы в публичной директории — отдавайте их через `download.php` (требует сессию, логирует загрузки) |
| 🔑 | Используйте сильные, уникальные пароли для каждого аккаунта |
