## 📬 Як повідомити про вразливість безпеки

> [!CAUTION]
> Повідомляйте про вразливості безпеки лише приватно, на **dev@secretkey.website** — ніколи як публічний Issue на GitHub. Публічне розкриття експлойту до випуску виправлення наражає на ризик усіх, хто має розгорнуту систему.

### Як повідомити

Надішліть детальний опис на: **dev@secretkey.website**

### Що включити у звіт

| | Елемент |
|---|---|
| 📝 | Опис вразливості та її потенційного впливу |
| 🔁 | Кроки для відтворення (proof of concept) |
| 🏷️ | Версія системи, якої це стосується |
| 💡 | Пропозиція виправлення *(необов'язково)* |

### Чого очікувати

| Час | Відповідь |
|---|---|
| **48 годин** | Підтвердження отримання звіту |
| **7 днів** | Інформація про прогрес |
| Після виправлення | Публічна подяка *(якщо забажаєте)* |

## 🏷️ Підтримувані версії

Завжди підтримується **остання випущена версія**. Звіти щодо старіших версій приймаються, але спершу просять оновитися до найновішого релізу — частина вразливостей може бути вже виправлена.

Актуальну версію можна знайти на [сторінці Releases](https://github.com/mateuszkarpierz/secret-key/releases).

## 🎯 Обсяг звітів

### ✅ У межах обсягу

- Обхід автентифікації (bcrypt, 2FA)
- Вразливості CSRF попри застосовані засоби захисту
- Можливість відновити секрет Шаміра без потрібної кількості фрагментів
- Розкриття даних із директорії `/private/`
- Завантаження чутливих файлів (наприклад, бази паролів) в обхід входу в систему, наприклад через прямий URL
- Вразливість до атак методом перебору (brute-force) попри rate limiting
- XSS, SQL Injection *(хоча система не використовує SQL)*

### ❌ Поза обсягом

- Атаки, що вимагають фізичного доступу до сервера
- Атаки соціальної інженерії на власників карток Secret Key
- Проблеми з конфігурацією веб-сервера на боці користувача
- Звіти, автоматично згенеровані сканерами без PoC

## 🛡️ Найкращі практики розгортання

> [!WARNING]
> Secret Key — це **самостійно розміщувана (self-hosted)** система — безпека вашого встановлення значною мірою залежить від конфігурації вашого власного сервера.

| | Практика |
|---|---|
| 📁 | Тримайте директорію `/private/` **за межами** `public_html` |
| 🔒 | Використовуйте HTTPS (SSL/TLS) на сервері |
| 🔄 | Регулярно оновлюйте PHP до найновішої версії 8.x |
| 🚫 | Ніколи не розкривайте файл `secret-key.php` публічно |
| 📥 | Не посилайтесь напряму на чутливі файли в публічній директорії — віддавайте їх через `download.php` (потребує сесії, логує завантаження) |
| 🔑 | Використовуйте надійні, унікальні паролі для кожного облікового запису |
